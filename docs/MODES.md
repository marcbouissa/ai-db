# Mode reference

Every mode ai-db exposes, in one place. Generated by `eval/render_modes_table.py` from `argparse` and from the module constants that define the modes, so it cannot drift.

Three different things get called a "mode", and conflating them is the usual source of confusion:

| Kind | Set by | Scope |
|---|---|---|
| **Query mode** | a flag on one command | that one invocation |
| **Config mode** | `config.json` or an env var | every invocation until changed |
| **Depth** | a flag, and often redundant | how much comes back |

## 1. Query modes

### `investigate --mode` — which question is being asked

| Mode | Question it answers | Extra requirement |
|---|---|---|
| `locate` | Where is it? Which files and entry points. | — |
| `explain` | How does it work? Bodies of the seed and its parents. | — |
| `impact` | What breaks if I change it? Callers and callees. | — |
| `flow` | What is the call path? Ordered edges through the graph. | — |
| `diff` | What changed in this commit range? | `--since` required |

`diff` is the only mode that needs history; the rest read the index as it stands. Mode choice changes the pack's *contents*, not its token budget.

### `analyze --format` — how the answer is rendered

| Format | Shape | Counts `tokens_out_formatted` |
|---|---|---|
| `json` | Full dict, machine-readable | **yes** — the only format that does |
| `stub` | Signature per symbol, no bodies | no |
| `sexp` | S-expression, one node per symbol | no |
| `outline` | Nested structural outline | no |
| `prose` | Readable narrative | no |

The token count is skipped for the four formats a human reads directly: loading tiktoken's encoder costs ~300 ms once per process against 0.9 ms per subsequent count, and `json` is the only format whose output is read by a machine that would look at `meta`.

Pack formats (`investigate --format`) are a **different** set: `compact`, `json`, `sexp`, `stub`. At the default 8,000-token budget `stub` is 8.9x smaller than `json` (3,607 vs 32,438 tokens).

### Depths

| Command | Depths | Default | Note |
|---|---|---|---|
| `analyze --depth` | `summary`, `structure`, `targeted`, `full` | `structure` | `summary` and `structure` are **byte-identical** (verified by md5) |
| `expand --depth` | `targeted`, `full` | `full` | `targeted` returns only the requested span |
| `trace --depth` | integer, unbounded | `TRACE_DEPTH` | max graph hops |

> Two names, one behaviour: `analyze --depth summary` and `--depth structure` produce the same bytes. The duplicate is kept for compatibility, not because the depths differ.

| Flag | Values | Notes |
|---|---|---|
| `check` | files on disk (default with a path), `--index` | Two different questions; both together is an error |
| `trace --format` | `tree`, `json`, `mermaid` | |
| `expand --format` | `json`, `raw` | |
| `todos --kind` | `todo`, `fixme`, `hack`, `note`, `xxx` | comment markers to look for |
| `todos --format` | `text`, `json` | |
| `optimize --default-format` | `stub`, `sexp`, `json`, `outline`, `prose` | persisted into session state |

## 2. Config modes (whole installation)

| Setting | Values | Default | Effect |
|---|---|---|---|
| `retrieval.mode` | `lexical`, `hybrid` | `lexical` | `lexical` is FTS/BM25 only and needs no model; `hybrid` fuses lexical with dense vectors weighted by `retrieval.doc_weight` |
| `storage.vector_index` | `exact`, `vec0` | `exact` | `vec0` uses the sqlite-vec extension, whose KNN is **also brute force** — it is not ANN, so the 10x target is unreachable on sqlite-vec 0.1.9 |
| `embedding.provider` | `none`, `sentence_transformers`, `openai_compatible`, `voyage` | `none` | `none` means lexical only |
| `embedding.device` | `auto`, `cpu`, `cuda` | `auto` | measured: CUDA 141.8x faster to index, 10.5x faster to query |
| `embedding.dtype` | `bfloat16`, `float16`, `float32` | `auto` | chosen by a timing probe, not a guess: float32 0.51 vs bfloat16 0.24 chunks/s measured, so bfloat16 only wins where the tensor cores exist |
| `rerank.provider` | `none` or a cross-encoder name | `none` | measured: `bAAI/bge-reranker-v2-m3` makes retrieval **worse** (MRR 0.785 → 0.555) at ~100x latency — a general MS-Marco model, not code-tuned |
| `index.ignore` | gitignore-style globs | `[".agents/**"]` | extended by `.aidbignore` at the project root |

Env-var overrides: `AI_DB_RETRIEVAL_MODE`, `AI_DB_PATH`, `AI_DB_CONFIG`, `AI_DB_SKILL_DIRS`.

## 3. Commonly mistaken for modes

| Thing | What it actually is |
|---|---|
| `ref:` handles | Opaque, **process-scoped** pointers minted by `analyze`/`investigate`. They do not survive a process exit, so `expand` cannot be scripted across invocations or benchmarked as a subprocess. |
| `--all-files` | Indexes everything under `--root` instead of only git-tracked files. Used by the polyglot eval. |
| `--budget` | A token budget for a pack, not a mode. A lower budget buys more stubs and omissions, never more tokens. |
| `meta.tokens_out` | A depth-derived **estimate** of content size, and it is format-blind: it does not change between `json` and `stub`. Use `meta.tokens_out_formatted` for real emitted size (CLI only). |

## Coverage and known gaps

| Area | Coverage |
|---|---|
| Languages parsed | 9 grammars across 16 extensions: c (`.c`, `.h`), cpp (`.cc`, `.cpp`, `.hpp`), go (`.go`), java (`.java`), javascript (`.cjs`, `.js`, `.jsx`, `.mjs`), python (`.py`, `.pyi`), rust (`.rs`), tsx (`.tsx`), typescript (`.ts`) |
| `check` file validation | tree-sitter for those 9, a per-extension linter for everything else, both through one `parse_source` path |
| `tokens_out_formatted` | **CLI only.** Over MCP/HTTP, `analyze` with a format returns a rendered string (no `meta` to carry the number) and without a format there is no formatted output to count. Closing that gap is a transport contract change, not a missing line. |
